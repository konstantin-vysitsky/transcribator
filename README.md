# Трансктибатор — голосовая диктовка в трее

Локальная диктовка на Windows через **GigaAM v3 e2e RNN-T** (Сбер) с автовставкой в активное поле и очисткой слов-паразитов.

## Быстрый старт

1. Установите **Python 3.11**.
2. Запустите `start.bat` — создаст `.venv`, установит зависимости, загрузит модель (~1–2 мин на CPU при первом запуске).
3. Для фонового режима: `start_background.vbs` (иконка в трее, без консоли).

## Горячая клавиша

По умолчанию: **F7**, режим **hold** (зажал — говоришь, отпустил — распознавание).

Настройки в `config.json` или через меню трея.

## Возможности

- Иконка в системном трее + панель статуса (запись / распознавание / обработка)
- История последних 3 транскрипций (клик → копирование)
- Автовставка + опциональный **Enter** после текста
- Кнопки на панели: «Автоотправка», «Обработка ИИ», «Готово», «✕» (отмена)
- Выбор режима клавиши (удержание / toggle)
- Настройка потоков CPU (1–10), перезагрузка из меню
- Автозапуск Windows через ярлык `Dictation.lnk`
- Удаление слов-паразитов («э-э», «как бы», «типа» и т.п.) после распознавания
- Обработка текста через LLM: чистка, пунктуация, чёткая формулировка (см. ниже)

## Модель

По умолчанию: **`v3_e2e_rnnt`** — GigaAM v3 end-to-end RNN-T от Сбера (PyTorch, CPU).

Модель сама расставляет пунктуацию и пишет числа цифрами. Кэш весов: `~/.cache/gigaam` (или `C:/gigaam-cache` при кириллице в профиле Windows).

Другие модели GigaAM задаются полем `model` в `config.json` (например `v3_e2e_ctc`, `v2_rnnt`, `multilingual_ctc`). Whisper не поддерживается.

## Очистка слов-паразитов

Включена по умолчанию (`"remove_fillers": true` в `config.json`).

После распознавания из текста убираются «э-э», «мм», «как бы», «типа» и другие слова из списка. Список редактируется в:

```
C:\Users\ВАШЕ_ИМЯ\.transcribator\fillers.json
```

Чтобы отключить очистку, поставьте `"remove_fillers": false`.

## Обработка текста через ИИ

Диктовка редко выходит готовой: остаются оговорки, повторы, обрывы, а мысль
размазана на длинную фразу. Обработка через ИИ прогоняет распознанный текст
через языковую модель и возвращает его чётким и читаемым — но **смысл не
меняется**. Это записано в промпте прямым запретом: модель не добавляет фактов,
не убирает сказанное и не переписывает фразы «красивее».

Обработка выключена по умолчанию: без ключа она не работает, и включать её
молча нельзя.

### Включение

1. Возьмите ключ в личном кабинете Token Seller (`https://федота.рф`) —
   раздел с API-ключом.
2. Положите ключ в `config.local.json` рядом с `config.json`:

```json
{
  "ai_api_key": "ваш-ключ"
}
```

3. Включите обработку: либо переключателем в меню трея («Обработка через ИИ»),
   либо `"ai_enabled": true` в `config.json`.

Файл `config.local.json` в git не попадает — ключ в репозиторий не уходит.
Можно положить ключ и прямо в `config.json`, но при сохранении настроек он
будет перенесён в `config.local.json` автоматически.

### Настройки

| Поле | Что задаёт | По умолчанию |
|---|---|---|
| `ai_enabled` | включена ли обработка при запуске | `false` |
| `ai_base_url` | адрес OpenAI-совместимого API | `https://xn--80ahc1bui.xn--p1ai/v1` |
| `ai_api_key` | ключ доступа (лучше в `config.local.json`) | пусто |
| `ai_model` | модель | `deepseek-v4-flash` |
| `ai_timeout_s` | сколько ждать ответ, секунды (5–120) | `30` |

Адрес по умолчанию — наш Token Seller, но поле открытое: подойдёт любой сервис
с OpenAI-совместимым `/v1/chat/completions`, включая сам `api.deepseek.com`.
Интерфейса для смены адреса нет намеренно — это правится в `config.json`.

### Кнопки на панели

Панель появляется при записи. Кроме прежних кнопок на ней новая:

- **Обработка ИИ вкл / выкл** — переключает обработку. Действует до конца
  сессии и в `config.json` не пишется: это решение «здесь и сейчас». Кнопка
  важнее настройки — если она выключена, текст вставится как распознан.

Надпись на кнопке говорит о готовности:

| Надпись | Что значит |
| --- | --- |
| `Обработка ИИ вкл` | включена, ключ на месте |
| `Обработка ИИ выкл` | выключена вручную |
| `ИИ вкл · ошибка` | включена, но последний запрос не прошёл |
| `ИИ не настроен: нет ключа` | ключа нет — включать нечего |

Причину отказа приложение пишет в уведомлении трея. Ключ перечитывается в
начале каждой диктовки, так что после правки `config.local.json` перезапуск
не нужен.

Кнопки промпта на панели нет: инструкцию правят из меню трея, а не на ходу
диктовки.

«Автоотправка» и «Обработка ИИ» — разные вещи: первая управляет клавишей
Enter, вторая — тем, идёт ли текст через модель.

### Промпт

Инструкция для модели лежит в `prompt.txt` в корне проекта. Открывается из меню
трея: «Промпт обработки…». Там же кнопка **Восстановить**, возвращающая готовый
текст по умолчанию, и **Сохранить**. Файла нет или он пуст — подставляется
готовый текст по умолчанию.

Промпт задаёт: убрать мусор устной речи, расставить знаки препинания и заглавные
буквы, разбить на абзацы, записать числа цифрами. Отдельно — исправление ошибок
распознавания: иностранные слова и названия, услышанные на слух, пишутся
латиницей в общепринятом виде («докер» → docker, «питон» → Python, «гет» → git,
«реакт» → React), разорванные и слитые слова восстанавливаются («в общем то» →
«в общем-то», «ни чего» → «ничего»). Исправлять разрешено только там, где
правильное слово однозначно понятно из контекста.

Промпт запрещает: менять смысл, факты, имена и числа, переписывать фразы,
переводить иностранные слова на русский или заменять русские слова
иностранными, угадывать непонятное, отвечать на сказанное, добавлять заголовки
и выводы.

### Если обработка не удалась

Текст вставляется как распознан, а в трее появляется уведомление с причиной:
«ключ отклонён», «закончились средства», «нет связи с сервисом» и т.п. Диктовка
не теряется из-за чужого сбоя — это проверено тестом.

### Если горячая клавиша не срабатывает

Приложение работает без окна, поэтому о своём состоянии оно пишет в
`dictation.log` в корне проекта. Если F7 не реагирует — сначала посмотрите туда:

- последняя строка «слушатель клавиш запущен: f7» — приложение работает, дело в
  перехвате ввода (см. ниже);
- строки нет вовсе либо есть «слушатель клавиш НЕ запустился» — нажатия не
  доходят до приложения;
- файла нет или он старый — приложение не запущено.

Частая причина: другое приложение запущено **от администратора**. Windows не
отдаёт нажатия процессу с меньшими правами, поэтому диктовка их не видит.
Закройте то приложение либо запустите диктовку тоже от администратора.

Второй экземпляр запускать не нужно: он молча выходит, и в журнале появляется
строка «второй экземпляр уже запущен».

## Сохранность записей

Каждая диктовка сохраняется в файл **сразу после остановки и до распознавания** —
в папку `записи\` рядом с проектом, в формате WAV, плюс расшифровка в `.txt` с тем
же именем. Записи **не удаляются после распознавания**: папка служит ещё и
собранием своей речи — примеров, надиктовок, удачных формулировок.

Хранятся последние **40** записей. Когда предел достигнут, самые старые
вытесняются по одной: папка не пустеет скачком, и заметить потерю есть время.
Вместе с записью уходит и её расшифровка.

Если распознавание не прошло (сбой, закрытие приложения, пустой текст), в
`dictation.log` появляется строка:

```
распознавание не завершилось, запись сохранена: 2026-10-12_12-13-58.wav
```

Такую запись можно открыть любым проигрывателем, а расшифровать отдельно:

```
.venv\Scripts\python.exe tests\транскрибировать.py
```

Без аргументов берётся самая свежая запись. Результат кладётся рядом в `.txt`.

Зачем это нужно: распознавание длинной диктовки занимает время, и до него
запись существует в единственном экземпляре — в оперативной памяти. Любой сбой
на этом пути раньше означал безвозвратную потерю.

Повторное нажатие горячей клавиши во время записи **не стирает** записанное:
второй запуск отклоняется, а в журнал пишется «запись уже идёт».

## Длинные записи

Запись длиннее 32 секунд режется на куски по 8–30 секунд и распознаётся по
частям. Это не оптимизация, а необходимость: **поданная целиком, длинная запись
не даёт текста вовсе.** Модель GigaAM обучена на коротких фразах, и на
нескольких минутах подряд обработка идёт, но результата нет — снаружи это
выглядит как зависание. Короткие фразы при этом работают, поэтому поломка
проявлялась только на длинной диктовке.

Режется по паузам, а не по секундам: разрез посреди слова теряет его окончание.
Внутри окна ищется самое тихое место, и разрез попадает в паузу.

На панели видно движение: «Распознаю… часть 3 из 15». Запись на 3.5 минуты
распознаётся примерно за 15 секунд.

## Проверки

```
.venv\Scripts\python.exe tests\check_ai.py               обработка без сети
.venv\Scripts\python.exe tests\check_ui.py               живые окно и панель
.venv\Scripts\python.exe tests\check_wiring.py           настройки, меню, решение
.venv\Scripts\python.exe tests\check_recording.py        запись не теряется
.venv\Scripts\python.exe tests\check_long_transcribe.py  длинная запись распознаётся
.venv\Scripts\python.exe tests\check_recording_live.py 4 запись с микрофона
.venv\Scripts\python.exe tests\check_hotkey.py           доходят ли нажатия клавиш
.venv\Scripts\python.exe tests\транскрибировать.py       расшифровать запись из папки
.venv\Scripts\python.exe tests\check_ai.py --live        запрос с вашим ключом
.venv\Scripts\python.exe tests\shot_panel.py             снимки панели и промпта
```

`check_long_transcribe.py` прогоняет настоящий код приложения на длинной записи
из папки `записи` — проверяет то, на чём пропадала диктовка.

`check_hotkey.py` слушает клавиатуру и печатает, что доходит. Запустите его и
нажмите F7: если нажатий ноль — ввод перехватывает другое приложение.

`check_ui.py` открывает окна по-настоящему: проверяется, что панель рисуется,
кнопки на месте, текст промпта доезжает до поля и «Восстановить» возвращает
дефолт. `--live` у `check_ai.py` ходит в сеть с ключом из настроек.

## Мини-клавиатура (USB remap)

Папка `c:\по восстановлению\прочее\usb-keyboard-remap\` — ремап Keychron mini (VID 8808 / PID 6601):

- `run\remap-mini-keyboard.ahk` — клавиша 1 → F9, клавиша 2 → F7
- `run\trigger-dictation.ps1` — UDP-сигнал `toggle` на порт 38721 (запасной путь)
- `dictation/remote_trigger.py` — слушает UDP в транскрибаторе

Запуск ремапа:
```
run\ahk\AutoHotkey64.exe run\remap-mini-keyboard.ahk
```
или просто `ЗАПУСК.bat`.

**Комплект восстановлен:** `run\ahk\AutoHotkey64.exe` (AutoHotkey v2.0.28),
`run\Lib\AutoHotInterception.ahk` + `.dll` и `run\Lib\x64\interception.dll`.
Драйвер Interception установлен, но активируется **после перезагрузки Windows**.
